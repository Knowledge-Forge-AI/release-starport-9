Root transport probe3 measured the exact API redirect host `productionresultssa12.blob.core.windows.net` and verified the root ZIP117311 bytes/SHA865cb279… plus inner65070c… package. The selection admits only that host; the code also fixes that exact host. HTTPS443/no userinfo/no fragment are required, and API authorization is dropped before any redirect. No wildcard, alternative host or user-supplied repository/URL/run/artifact selector is accepted. Any storage-host change requires another measured/reviewed source selection change; it cannot broaden itself at runtime. This transport observation is not native qualification.

The qualification-only workflow runs the maintained local-input builder and unchanged hosted three-target jobs/matrix. Native receipts bind the RS9 checkout/current qualification run, while the transport receipt separately binds the upstream producer run. All qualification results retain publication admission false. A successful native matrix does not modify source readiness, pins or approved publication records.

After RS9 public source acceptance, render the Solar-owned workflow with required `--rs9-commit` and review/commit that generated output in Solar before dispatch; see `../actions/README.md`. RS9 does not retain an active qualifier workflow: its repository-scoped job token cannot grant Solar artifact ZIP access. Every job explicitly checks out the accepted RS9 commit; native expected-commit uses that tooling identity while run ID/attempt remain the real Solar caller. The sole new CLI is `python3 -B -m rs9.tf_pypi_actions_intake --output transport`; the workflow then calls `rs9.tf_pypi_publish build --project theme-forge-solar-sail --pin operators/tf-pypi/theme-forge-solar-sail-0.3.0.json --inputs transport/inputs --output dist`. Output must be fresh. Transport retains authenticated API records/ZIPs. On post-allocation failure it preserves the primary exception and attempts a failure receipt only while the structural owner token still proves the fresh output root. Ownership loss or a receipt-write error returns nonzero with failurePersistenceUnknown and bounded retention facts on stdout; it never writes into a replacement directory or promises a durable fallback there. Pre-allocation refusal likewise returns nonzero and a bounded status on stdout.

The exact inner pack is byte-copied under the versioned pin basename, never repacked or installed by transport. Source-policy, root-package and aggregate receipts/manifest rows must agree. All30 nested aggregate artifact rows are independently selected and require exact path/byte-count/SHA equality; their row shape, normalized relative paths, case-insensitive uniqueness, integer sizes and full digests are validated before use. An uploaded artifact from a failed run is refused, as are expired artifacts and mismatched source trees. An empty run API pull_requests list after merge is allowed only with the explicit PR API/receipt/source-commit joins.

Normal GitHub artifact expiration is a hard refusal. A new run requires a separately reviewed source/pack/selection change; no latest or release fallback exists. Release publication and subsequent RS9 READY/approval admission remain separate. The existing publisher still requires its own same-run native matrix and protected manual publish gates; qualification receipts cannot be transplanted between runs.

No dependency, lock, runtime-class or test-runner-policy changes. No closed runtime wheel helper allowlist registration is needed: these two source/operator modules are never bundled into product artifacts.
