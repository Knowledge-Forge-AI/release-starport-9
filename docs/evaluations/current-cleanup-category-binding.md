# Current harness cleanup diagnostic binding

The installed container route can run authenticated Nebular 0.7.1 source without enabling the optional Nix observer. Previously, the existing fixed cleanup-failure category depended on observer activation. A failed cleanup could therefore contribute only to the unrecognized count.

After an original Linux failure, the existing complete current-source profile verifier now separately controls recognition of that fixed category. Generation or version text alone is insufficient. Unknown or changed source retains the previous withholding behavior. No observer is enabled, no process is retried, and existing gates, limits, environments, raw-log withholding, category schema and optional finalization-field routing remain unchanged.

This corrects a diagnostic gap. It does not identify the cause of the retained ARM64 DEB failure or establish native qualification. The previous isolated job recheck stopped at attempt-bound input custody, before application execution; a fresh qualification campaign must begin with authentication.
