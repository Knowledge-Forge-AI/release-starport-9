# Required current summary context

Status: private prepare-only correction to review2 B1; no activation or qualification claim.

Every current-generation summary validator, including the public hosted summary API, requires an original-run context admitted from fresh original RS9 metadata. Missing context fails with HOSTED_RUN_CONTEXT under both a packages-repository environment and spoofed RS9-like environment variables. Producer provenance remains a separate strict emitter. Historical summary validation behavior is unchanged. Legitimate synthetic summary tests explicitly admit fixture original-run metadata; the current RPM policy remains held and its test still reaches CURRENT_RPM_POLICY_HELD.

The actual PublicClient.json signature accepts a required request_class keyword and forwards additional keywords to get, which accepts limit and no_redirect. PublicClient(api_token=None) builds a proxy-disabled opener without an authorization handler. A controlled HTTPS-handler test exercises the actual default PublicClient, JSON parser and opener stack with ambient GH_TOKEN, GITHUB_TOKEN and HTTPS_PROXY variables. The captured request is GET without authorization or cookies and requests no redirects. The real metadata path therefore has no signature mismatch or ambient-token injection in this test. No remote request was made. Relay CDN query admission is unchanged pending separately authorized observation of real public redirects.

Downstream integration must set PYTHONDONTWRITEBYTECODE=1 before importing RS9 from its source checkout, or establish appropriate tracked ignore policy, so verification itself does not introduce untracked bytecode caches. Consumers must preserve the adopted checkout and rehash each returned physical origin against its returned size and SHA-256 immediately before use. They must also recompute the selected source/configuration identity at their use boundary; returned paths and hashes are evidence, not authority to skip revalidation or to sign or publish.

Debian and pacman installable roles in this facade rely on authenticated producer custody, declared paths, hashes and existing architecture consistency checks. This revision adds no independent Debian or pacman byte-format parser. RPM byte-role parsing remains the existing explicit check. Successful synthetic context tests isolate held policy admission, real binary input selection and source-tree success on the non-Git snapshot; they establish control flow rather than native acceptance.

Advisories about losing per-lane diagnostics when consumer source identity itself fails and preserving an earlier lane execution cause during a failed final identity recheck remain diagnostic refinements outside this narrow API correction. They do not enable qualification: identity failure remains fail-closed. No diagnostic behavior, primary-cause policy, workflow, contract, relay URL admission, production authority or native parser was broadened here. Previous review inputs and seals remain preserved.
