# ADR 0019: Nebular native Darwin ARM64 PyPI publisher and qualification

Status: qualification candidate; `publication_admitted` remains `false`.

## Context

The pending PyPI Trusted Publisher for `theme-forge-nebular-fusion` (`0.6.1`) is now registered with owner `Knowledge-Forge-AI`, repository `release-starport-9`, workflow `rs9-tfnf-pypi-publish.yml`, and environment `pypi`. Unlike the first-wave Node CLI adapters (`theme-forge-stellar-burst`, `theme-forge-stellar-loom`, `theme-forge-solar-sail`), Nebular Fusion is a native Tauri/Rust desktop and headless studio application whose released payload is the authenticated compressed macOS application bundle (`theme-forge-nebular-fusion-v0.6.1-aarch64-apple-darwin.app.tar.gz`, 47,079,690 bytes, SHA-256 `e5ab9c5ce5dd7fb02274b11b223db9db7ac1f3b2167334ee2f322abd3c8ec4be`).

## Decision

1. **Extend the existing PyPI adapters with a native Nebular publisher**:
   - Preserve the first-wave Node CLI adapters while adding the Nebular native wheel, qualification harness, repeat-upload guards, and dedicated workflow.
   - Qualify the exact clean public source commit before hosted qualification or publication admission.

2. **Truthful `Requires-Python: >=3.10` with unchanged embedded helpers and full package AST floor verification**:
   - Preserve the five reviewed embedded runtime helpers (`archives.py`, `errors.py`, `materialize.py`, `scratch.py`, `security.py`) byte-for-byte inside `theme_forge_nebular_fusion/_isolated/rs9/`.
   - Because `src/rs9/scratch.py:92` evaluates `int | None` at class definition time without `from __future__ import annotations`, the static and runtime floor of the unchanged helper closure is Python 3.10.
   - Update `src/rs9/wheel_native.py` to emit `Requires-Python: >=3.10`, and have `analyze_embedded_python_floor` parse all shipped Python sources (`theme_forge_nebular_fusion/__init__.py`, rendered `theme_forge_nebular_fusion/launcher.py`, and all embedded `_isolated/rs9/*.py` helpers) with `ast.parse(..., feature_version=(3, 10))` plus a heuristic `>=3.11` stdlib/builtin denylist (`PY311_PLUS_STDLIB_MODULES`, `PY311_PLUS_STDLIB_ATTRS`, `PY311_PLUS_BUILTINS`, `PY311_PLUS_QUALIFIED_ATTRS`), while recording Python `3.10`–`3.12` as `not-executed-locally`.
   - Record the superseded preliminary `>=3.9` wheel (`7d2bcbee182e496fa6221e1b2dad75e7899373aba7801f17a16a838f843ae82c`, 46,792,719 bytes) in `superseded_candidates` and reject it in schema and candidate inspection.
   - Verify that a real Python 3.9 interpreter (`3.9.6`) refuses the `>=3.10` wheel (`7f38708f9e82216b27165769785b378f5b17480a8a7a594f07adf6273e737c20`, 46,792,720 bytes) before installation while leaving the virtual environment unchanged. Note that `python_floor_basis.executed_interpreters` in the committed manifest is a qualification attestation bound at manifest-generation time (`approval_document`) and backed by the offline consumer qualification reports, rather than re-executed inside `build_candidate` during wheel build.

3. **Wheel-only Darwin ARM64 scope, single top-level `Info.plist` anchoring, and non-vacuous cross-zlib byte reproducibility**:
   - Approve only `theme_forge_nebular_fusion-0.6.1-py3-none-macosx_13_0_arm64.whl` (`Root-Is-Purelib: false`, derived from `LSMinimumSystemVersion` `13.0` in the single top-level bundle `Contents/Info.plist`). Both `wheel_native.py` and `tf_pypi_nebular.py` anchor `TOP_LEVEL_PLIST_RE` (`(?:\./)?(?:[^/]+\.app/)?Contents/Info\.plist`) in `_extract_plist_from_payload_tar`, scan the entire payload archive without early break, ignore nested framework/helper plists, and fail closed (`ContractError("INVALID_PLIST")` / `TF_PYPI_WHEEL_PLIST_DUPLICATE`) if zero or multiple top-level bundle `Contents/Info.plist` members exist.
   - Emit no sdist (wrapping a precompiled native application binary in an sdist is not a source distribution) and keep Linux candidate wheels (`linux_x86_64`, `linux_aarch64`) withheld from publication (`can_publish: false`, `manylinux_proven: false`).
   - Pin `actions/setup-python@ece7cb06caefa5fff74198d8649806c4678c61a1` with `python-version: '3.13'` in `rs9-tfnf-pypi-publish.yml` and verify bit-for-bit identical ZIP output across `zlib 1.3.2` (Python 3.13.12) and `zlib 1.2.12` (macOS system Python 3.9.6) via in-repo `verify_cross_zlib_wheel`. When the alternate interpreter is absent, `verify_cross_zlib_wheel` returns `status: "alternate-interpreter-absent"` and `matches_primary: None`, and `approval_document` fails closed (`TF_PYPI_CROSS_ZLIB_UNVERIFIED`) unless at least two distinct zlib versions are verified.

4. **Legal separation and PyPI file-size headroom**:
   - Ship only `LICENSE` (34,460 bytes, `62eef07fc3ad238dd889ff98cf9ed87b3ef0f421579b6945f87ec37c608afb62`) and `NOTICE` (604 bytes, `9b7be934e0a179a7c48446139334470964057c198d49ec8e149c3101f78778f2`) in `.dist-info/licenses/` with `License-Expression: AGPL-3.0-or-later`.
   - Retain `COMMERCIAL-LICENSE.md` (933 bytes, `3f5ea7c51359c8d4310e061686980c674151b20924f6cd2bb59d657566e6c30f`) as authenticated tagged source evidence with `shipped_in_wheel: false`.
   - Record the 46,792,720-byte wheel against PyPI's 100,000,000-byte default per-file limit (53,207,280 bytes headroom).

5. **Enforced seatbelt network denial with bounded `/bin/ps` exception and non-enumerating host-state observer**:
   - Run real installed-wheel qualification under `/usr/bin/sandbox-exec` with `(version 1)(allow default)(deny network*)(allow process-exec (with no-sandbox) (literal "/bin/ps"))`.
   - Prove active Python (`s.connect(('1.1.1.1', 443))` -> `EPERM`/`EACCES` and `socket.getaddrinfo('registry.npmjs.org', 443)` -> `socket.gaierror` `EAI_*`) and Node literal-IP TCP (`1.1.1.1:443`) and DNS (`registry.npmjs.org`) denial independently inside the sandbox.
   - Verify that `ps` resolves on the harness `PATH` to root-owned, non-symlink `/bin/ps` (`uid == 0`, `mode in (0o4755, 0o0755)`, SHA-256 recorded for audit), probe only `ps -p <self-pid> -o pid=,comm=`, require a single output line whose first whitespace-delimited token equals `str(os.getpid())`, and retain no raw process-table output.
   - Snapshot the exact 63 Darwin persistent-state locations (`7` Library bases × `3` application names × `3` suffixes, verified against `persistentStateLocations` in `native-rc-smoke.mjs`) beneath the real operator home directory (`pwd.getpwuid(os.getuid()).pw_dir`) before and after qualification without ever enumerating shared `~/Library/*` parent directories; hash any existing descendant subpaths (`sha256:...`) and write only `public_summary` aggregates to `host-state-before.json` / `host-state-after.json`.

6. **Three-job workflow, clean-checkout artifact staging, mandatory paginated prior-run guard, and finite post-upload readback**:
   - Materialize `.github/workflows/rs9-tfnf-pypi-publish.yml` with `build_verify` (`macos-15`), `native_consumer` (`macos-15`, downloading `pypi-artifacts` to `${{ runner.temp }}/tfnf-dist` outside `$GITHUB_WORKSPACE` so `qualify --require-clean` runs against an untouched checkout), and `publish` (`ubuntu-24.04`, `environment: pypi`, `permissions: {id-token: write, contents: read, actions: read}`).
   - Keep `builder_can_publish: false` and `publication_admitted: false` in `operators/tf-pypi/theme-forge-nebular-fusion-artifacts.json` (`set_sha256: 5b306dfabae76d597263ea2ddd563d7d11211b252eba910eca45672a0a939284`, invariant across `publication_admitted`).
   - Enforce an intra-job exclusive upload marker (`--attempt-marker`), job-rerun refusal (`GITHUB_RUN_ATTEMPT != '1'`), durable repository/environment variable refusal (`vars.RS9_TFNF_PRIOR_UPLOAD_UNCONFIRMED`), and a mandatory GitHub Actions prior-run check (`check_prior_publish_runs` using `RS9_GITHUB_READ_TOKEN: ${{ github.token }}`) that pages through workflow runs and jobs (`filter=all&per_page=100`, up to `MAX_PRIOR_RUN_PAGES = 10`, failing closed on truncation or missing `total_count`) and requires every unreviewed prior `workflow_dispatch` run on `main` to include the `Trusted Publishing to PyPI` job (failing closed if absent) and have `conclusion == "skipped"` on that job or on every `"Publish package distribution to PyPI"` step (`status == "completed"`). If a prior `publish` run failed or was cancelled before uploading, recovery requires independent operator readback of PyPI and GitHub Actions logs followed by recording the audited run ID in `REVIEWED_SAFE_PRIOR_RUN_IDS` via a reviewed commit.
   - Run pre-upload `verify-upload`, explicit `pypa/gh-action-pypi-publish` flags (`verify-metadata: true`, `print-hash: true`, `skip-existing: false`, `attestations: false`), and an intra-job finite 6-attempt post-upload `readback` schedule `(0, 15, 30, 60, 120, 180)` seconds that never re-invokes upload.

## Consequences and what would make this wrong

- Local qualification proves the deploy-equivalent source candidate on macOS ARM64 (`3.13.12` full lifecycle + sidecar + Darwin Scenario A, `3.9.6` pre-install refusal) and records `source_state` (`worktree_clean`, `product_files_sha256`, `closure_files_count`, `closure_files_sha256` across the 84-file transitive `src/rs9/*.py` import closure + product and authority manifests, and `serena_excluded_from_dirty_check: true` so operator-local `.serena/` metadata is neither read nor treated as product dirtiness). Pre-commit offline qualification reports (`worktree_clean: false`) bind the candidate overlay via `product_files_sha256` and `closure_files_sha256` rather than claiming a clean committed Git tree; hosted `native_consumer` enforces `--require-clean` on the committed checkout.
- Network-denial validation derives its allowed Python DNS error set from the host libc `socket.EAI_*` constants (`EAI_NONAME`, `EAI_AGAIN`, `EAI_FAIL`, `EAI_NODATA`) with unit tests using portable `socket.EAI_*` fixtures across Darwin and Linux/glibc rather than platform-specific integer literals; unexpected prior-run client or assertion failures in `check_prior_publish_runs` (including `AssertionError`) map fail-closed to `TF_PYPI_PRIOR_ATTEMPT_UNCONFIRMED` before staging or upload; and the hosted Linux `unit` CI gate remains pending until executed on the exported candidate.
- Any drift in authenticated release captures, verifier source closure (`bc8075c4ab1a8587ba9f1abeaef024aa894cc6403b0466e35c5022ff387980f9`), embedded helper bytes, wheel digest, or host-state isolation invalidates qualification and fails closed.
